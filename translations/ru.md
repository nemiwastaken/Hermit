# Hermit

Домашний агент: живёт на твоём сервере, управляется из Telegram, работает с
файлами и командами в изолированном контейнере. Профиль, память и скиллы лежат в
git — поведение меняется коммитом и откатывается одной командой.

## Установка

Нужны Linux, systemd и Docker с compose. Rust нужен только для сборки — ставь
через rustup от своего пользователя, установщик сам найдёт `cargo`.

```sh
curl -fsSL https://raw.githubusercontent.com/nemiwastaken/Hermit/main/install.sh | sudo bash
```

Установщик скачает исходники, соберёт ядро и образы, создаст каталоги, заведёт
git-репозиторий поведения, поставит systemd-юнит и запустит всё. Спросит токен
бота и ключ LLM.

Повторный запуск — это обновление: конфиг, база и `behavior/` не перезаписываются,
бинарник подменяется атомарно. Всё лежит в `/opt/hermit` (`hermit.env` с
секретами, `behavior/`, `workspace/`, `data/hermit.db`, `mcp.json`), кроме юнита
systemd.

## Возможности

- **Telegram**: long-poll, только личные чаты и только из белого списка. Ответ
  стримится в одно сообщение, «печатает…» висит и во время вызова инструментов.
- **Вложения**: отправь файл или фото с подписью, например «Кратко перескажи
  этот PDF». Hermit читает текст, DOCX и PDF с текстовым слоем и распознаёт
  текст на изображениях в офлайн-песочнице.
- **Очередь в SQLite**: сообщение переживает перезапуск и падение.
- **Модель**: любой OpenAI-совместимый endpoint, по умолчанию DeepSeek.
- **Инструменты**: `bash` (argv, без шелла), файлы `read`/`write`/`edit`/`patch`,
  поиск `glob`/`grep`/`list`, фоновые процессы `process_manage` и `execute_code`
  — Python, который сам вызывает инструменты.
- **Интернет**: `web_search` (DuckDuckGo без ключа) и `web_fetch` (текст страницы
  в Markdown) работают в сетевом контейнере.
- **Браузер**: Obscura выполняет JavaScript, переходит по ссылкам, заполняет
  формы и управляет вкладками. Скриншоты и PDF приходят файлами в Telegram.
- **Память и поведение**: `USER.md` и `MEMORY.md` в git, изменения через
  инструменты с коммитом, `/rollback` откатывает последнее.
- **Профиль агента и скиллы**: [HERMIT.md](../core/behavior/HERMIT.md) описывает
  агента и перечисляет [встроенные справки](../core/behavior/skills). Полный
  текст справок и пользовательских скиллов агент читает по запросу через
  `skill(name)`. Предпочтения хранятся в `USER.md`, долговременные факты — в
  `MEMORY.md`.
- **Сессии**: закрытые диалоги уходят в архив; прошлые находятся вопросом,
  `/sessions` или `recall`. Старше 30 дней — удаляются.
- **Контекст**: `/compress` заменяет переписку сводкой и последним обменом; при
  100k символов это происходит само.
- **Расписания без модели**: напоминания и трекеры — вопрос, число и среднее
  считает SQLite, а не LLM.
- **Расход**: `/usage` и `/insights` показывают токены и цену из SQLite; цена
  считается, если заданы `LLM_PRICE_IN_PER_M` и `LLM_PRICE_OUT_PER_M`.
- **MCP**: удалённые HTTP-серверы добавляют свои инструменты на старте.
- **Защита**: опасные команды (`rm -rf`, `mkfs`, `dd`, `reboot`…) ждут кнопки в
  Telegram; `/dlq` и `/retry` разбирают упавшие события.

## Вложения Telegram

Файлы до 20 МБ хранятся 30 дней и доступны на чтение по пути `/attachments`
в общей офлайн-песочнице. Агент получает короткий предпросмотр текста из
текстовых файлов, DOCX, PDF с текстовым слоем и изображений JPEG, PNG и WebP.
Аудио, видео и прочие двоичные файлы доступны инструментам в исходном виде.
Чтобы модель с поддержкой изображений в Chat Completions могла видеть
изображения до 5 МБ, укажи `LLM_VISION=1` в `hermit.env`.

При локальной разработке выполни `mkdir -p .dev/attachments` перед запуском
Compose. При изменении `HERMIT_ATTACHMENTS_DIR` укажи одинаковый путь в
настройках ядра и Compose.

## Как устроено

Главное правило: **ядро ничего не исполняет**. Оно умеет только «имя инструмента
+ JSON аргументов → JSON результат» и говорит с контейнерами по unix-сокету.
Модель не может выполнить код в ядре. `bash` работает без сети. Сетевому
контейнеру и браузеру недоступны рабочая папка и база данных.

| Часть | Что делает | Где живёт |
|---|---|---|
| **Ядро** `core/` | LLM, очередь, Telegram, политика инструментов | бинарник на хосте, systemd |
| **Поведение** `behavior/` | профиль, память, скиллы — попадают в промпт | git-репо `/opt/hermit/behavior` |
| **Песочница** `sandbox/` | исполняет `bash`, файлы, поиск, процессы | Docker без сети |
| **Сеть** `net/` | `web_fetch`, `web_search`, удалённый MCP | Docker с доступом в интернет |
| **Браузер** `browser/` | Obscura и его MCP-инструменты | Docker, отдельная сеть и Unix-сокет |
| **Рабочая папка** `workspace/` | всё, с чем работает агент | `/opt/hermit/workspace` |

Установщик создаёт `behavior/` и `workspace/`. При локальной разработке данные
хранятся в игнорируемой Git папке `.dev/`.

## Браузер

Установщик запускает Obscura на Linux x86-64 и ARM64. Например, напишите боту
«Открой https://example.org и пришли скриншот». Вкладки, cookies и состояние
страниц хранятся в памяти отдельно для каждого чата. Hermit сохраняет четыре
последние использованные сессии и сбрасывает их при перезапуске контейнера.
Obscura по умолчанию блокирует локальные файлы и адреса частных сетей.

Для локального запуска создайте `.dev/run/browser/` перед запуском Compose и
задайте `BROWSER_SOCKET=./.dev/run/browser/browser.sock` в `.env`.

## Команды

Отвечаются сразу, модель не вызывается:

| Команда | Что делает |
|---|---|
| `/pause`, `/resume` | остановить и продолжить разбор очереди |
| `/safe`, `/safe off` | выключить и вернуть инструменты |
| `/status` | пауза, safe mode, очередь, контекст, архив |
| `/new`, `/clear` | закрыть диалог в архив / удалить контекст чата |
| `/sessions` | list, `<id>`, `resume`, `rename`, `delete` |
| `/memory` | профиль, память и скиллы, которые видит агент |
| `/compress` | сжать контекст в сводку |
| `/usage`, `/insights [дней]` | расход за сегодня и 7 дней / по дням |
| `/changes`, `/rollback` | история поведения и откат последнего изменения |
| `/dlq`, `/retry <id>` | упавшие события и возврат в очередь |
| `/help` | список |

## Кодинг из Telegram

Из локального Git-репозитория запусти `sudo ./install.sh --with-coding`, чтобы добавить Rust-песочницу и проект Hermit. В образ входят зависимости из lockfile для сборки без сети. Другие проекты можно настроить в `/opt/hermit/projects.json` по образцу `install/projects.json.example`. Укажи путь репозитория внутри контейнера и команду проверки массивом аргументов.

Выбери `/project hermit` и отправь `/code <задача>`. Hermit создаст Git worktree, запустит проверку до и после правок и пришлёт результаты с кнопками для просмотра diff, доработки и принятия. При принятии Hermit коммитит проверенные изменения в ветку задачи. Состояние хранится в SQLite, поэтому ядро может продолжить задачу после перезапуска.

Чтобы дать конкретной установке доступ к диску хоста, запусти `sudo ./install.sh --host-disk`. Диск доступен песочнице по пути `/host` с правами пользователя установки, включая запись там, где она ему разрешена. Настройка включается явно и сохраняется при обновлениях.

## MCP

`/opt/hermit/mcp.json` — массив удалённых HTTP-серверов (Streamable HTTP):

```json
[
  {
    "name": "github",
    "url": "https://api.githubcopilot.com/mcp/",
    "headers": {"Authorization": "Bearer ..."},
    "approval": true
  }
]
```

Инструменты появляются у модели с именами `mcp__<сервер>__<инструмент>`.
`approval: true` требует кнопку на каждый вызов, `allow_private: true` разрешает
сервер в домашней сети (по умолчанию приватные адреса отбиваются как у
`web_fetch`). `stdio` не поддерживается. После правки запусти
`docker compose -f /opt/hermit/compose.yml restart net` — бот подхватит новые
инструменты в течение минуты.
