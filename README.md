# Hermit

Домашний агент: живёт на твоём сервере, управляется из Telegram, работает с
файлами и командами в изолированном контейнере. Своё поведение (профиль и
скиллы) держит в git и сможет менять сам — с возможностью откатить одной командой.

Английский аналог первой строки: a self-hosted Telegram agent with a sandboxed
shell, a git-tracked behavior layer, and an LLM-only core.

## Как устроено

Четыре части, у каждой ровно одна работа:

| Часть | Что делает | Где живёт | Кто меняет |
|---|---|---|---|
| **Ядро** `core/` | соединение с LLM: собирает контекст, вызывает модель, разбирает tool-calls, ведёт очередь и Telegram | бинарник на хосте, systemd | только ты, через git репозитория |
| **Поведение** `behavior/` | профиль и скиллы: файлы, которые попадают в системный промпт | отдельный git-репо, `/opt/hermit/behavior` | агент через `update_behavior` (срез 3), ты — руками |
| **Песочница** `sandbox/` | исполняет `bash` и читает файлы, обрезает вывод | Docker-контейнер без сети | никто напрямую: только через сокет |
| **Рабочая папка** `workspace/` | всё, с чем работает агент: проекты, конфиги, результаты | `/srv/hermit/workspace` | агент |

В репозитории лежат только `core/`, `sandbox/` и установщик. `behavior/` и
`workspace/` — это данные запущенного экземпляра, они создаются при установке;
в чекауте для разработки их заменяет один игнорируемый `.dev/`.

Главное правило: **ядро ничего не исполняет**. Оно умеет только «имя инструмента
+ JSON аргументов → JSON результат» и разговаривает с песочницей по unix-сокету.
Модель не может выполнить код в ядре — у неё просто нет такого пути.

```
Telegram ⇄ ядро (Rust, systemd, БД SQLite)
                │  JSON-строка на /srv/hermit/run/sandbox.sock
                ▼
        песочница (Docker: network none, read-only, cap_drop ALL)
                │
                ▼
        /srv/hermit/workspace + behavior/:ro
```

## Что умеет сейчас

- Telegram: long-poll, белый список чатов, длинные ответы режутся на части.
- Очередь событий в SQLite (WAL): сообщение переживает перезапуск и падение.
- LLM любой OpenAI-совместимый; по умолчанию DeepSeek (`deepseek-chat`).
- Инструменты: `bash` (argv-массив, без шелла) и `read`. Ответ инструмента
  обрезается до 100+100 строк, полный вывод остаётся в `/workspace/.tmp/`.
- Слэш-команды отвечают детерминированно, без вызова модели.
- `--safe-mode`: процесс поднимается с выключенными инструментами.

Чего ещё нет: расписания, `update_behavior` и `/rollback`, метрики, кнопки
подтверждения, асинхронный `bash`, квоты. Порядок работ — в разделе «Дорожная карта».

## Дорожная карта

1. **Позвоночник** — готов: Telegram → очередь → LLM → sandbox → ответ.
2. **Очередь и расписания** — минутный тик, таблица `schedules`, инструмент
   `manage_schedule`. Проверка: «напомни в 10:00» переживает перезапуск.
3. **Поведение** — `update_behavior` (валидация → git commit), `/rollback`,
   `/changes`, `/memory`. Проверка: агент меняет тон, ты откатываешь командой.
4. **Метрики** — таблица `metrics` + `log_metric`/`query_metrics`: цифры из SQL,
   а не из головы модели.
5. **Защита от ошибок** — кнопки `[Approve]`/`[Deny]`, асинхронный `bash` с
   `task_id`, квоты, DLQ-реплей, карантин расписаний, автооткат по аномалиям.

## Установка

Нужны: Linux, systemd, Docker с compose, Rust (только для сборки).

```sh
git clone <этот-репозиторий> ~/hermit && cd ~/hermit
sudo ./install/install.sh
```

Скрипт спросит токен бота и ключ LLM, соберёт ядро, скачает и соберёт образ
песочницы, создаст каталоги, заведёт git-репозиторий поведения, поставит
systemd-юнит и запустит всё. Повторный запуск — это обновление: конфиг, база и
`behavior/` не перезаписываются.

Флаги: `--no-start` (только разложить файлы), `--skip-build` (взять уже
собранный бинарник), `--no-systemd` (без юнита).

После установки:

```
/opt/hermit/bin/hermit        бинарник ядра
/opt/hermit/sandbox/          Dockerfile и server.py песочницы
/opt/hermit/behavior/         твой git-репо: профиль и скиллы
/opt/hermit/compose.yml       описание контейнера песочницы
/etc/hermit/hermit.env        секреты и пути, режим 600
/var/lib/hermit/hermit.db     база (очередь и история чатов)
/srv/hermit/run/              сокет
/srv/hermit/workspace/        рабочая папка агента
```

### Обновление

```sh
cd ~/hermit && git pull
sudo ./install/install.sh
```

Тот же скрипт: собирает новую версию, пересобирает образ песочницы, подменяет
бинарник атомарно (через `mv`, поэтому работающий процесс не мешает) и
перезапускает сервис. Конфиг, база и `behavior/` не трогаются. Если сломается
сборка образа — старая версия продолжает работать: бинарник меняется только
после успешного шага с песочницей. Что реально стоит сейчас:

```sh
/opt/hermit/bin/hermit --version
systemctl status hermit
```

### Первый запуск бота

1. Напиши боту в Telegram. Если твой чат не разрешён, он ответит его id.
2. Впиши id в `TELEGRAM_ALLOWED_CHAT_IDS` в `/etc/hermit/hermit.env`.
3. `sudo systemctl restart hermit`.
4. Проверка: «что лежит в /workspace?».

Логи: `journalctl -u hermit -f`.

## Настройка

Всё в `/etc/hermit/hermit.env` (переменные окружения, формат `KEY=value`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен от @BotFather, обязателен |
| `TELEGRAM_ALLOWED_CHAT_IDS` | пусто | id чатов через запятую; пусто = никого не пускать |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI-совместимый endpoint |
| `LLM_API_KEY` | — | ключ провайдера, обязателен |
| `LLM_MODEL` | `deepseek-chat` | модель |
| `LLM_MAX_TOKENS` | не задано | ограничение ответа |
| `DATABASE_PATH` | `/var/lib/hermit/hermit.db` | SQLite |
| `SANDBOX_SOCKET` | `/srv/hermit/run/sandbox.sock` | сокет песочницы |
| `BEHAVIOR_DIR` | `/opt/hermit/behavior` | откуда читать профиль и скиллы |

Пути в юните systemd рассчитаны на раскладку по умолчанию. Если переносишь
каталоги — правь и `/etc/systemd/system/hermit.service`.

## Команды

Отвечаются сразу, модель для них не вызывается:

| Команда | Что делает |
|---|---|
| `/pause` | перестать разбирать очередь (сообщения копятся) |
| `/resume` | продолжить |
| `/safe` | выключить инструменты, отвечать только текстом |
| `/safe off` | вернуть инструменты |
| `/status` | пауза, safe mode, длина очереди |
| `/clear` | забыть контекст этого чата |
| `/help` | список |

`/rollback`, `/changes`, `/memory` появятся вместе с git-историей поведения.

## Разработка

Репозиторий — это исходники; развёрнутая копия в `/opt/hermit` с ним не связана.
Всё, что появляется во время запуска (сокет, база, рабочая папка, твоя копия
поведения), живёт в одном игнорируемом каталоге `.dev/`:

```sh
cp .env.example .env && chmod 600 .env     # вписать токен и ключ
mkdir -p .dev/run .dev/workspace
cp -r behavior.example .dev/behavior
docker compose up -d --build
cd core && cargo run --release
```

`rm -rf .dev` — и от запуска не осталось следов. В продакшене те же роли играют
`/srv/hermit/run`, `/srv/hermit/workspace`, `/var/lib/hermit` и `/opt/hermit/behavior`.

Тесты:

```sh
cd core && cargo test && cargo clippy --all-targets
python3 sandbox/server.py --selftest
```

Структура исходников:

```
core/src/main.rs        сборка всего вместе, воркер очереди
core/src/telegram.rs    long-poll, белый список, отправка
core/src/events.rs      SQLite: очередь, история, kv
core/src/llm.rs         OpenAI-совместимый клиент
core/src/run.rs         цикл агента: контекст → модель → политика → инструменты
core/src/policy.rs      что разрешено (deny by default) и схема инструментов
core/src/sandbox.rs     клиент сокета песочницы
core/src/prompt.rs      системный промпт + файлы поведения
core/src/cmd.rs         слэш-команды и флаги процесса
sandbox/server.py       исполнение bash/read, обрезка вывода
install/install.sh      установка в систему
```

## Протокол с песочницей

Одна строка — один запрос, одна строка — ответ:

```json
→ {"id":"e42/7","tool":"bash","args":{"cmd":["rg","-n","TODO","src"],"cwd":"/workspace","timeout_ms":30000}}
← {"id":"e42/7","ok":true,"exit":0,"stdout":"…","stderr":"…","truncated":{"full_path":"/workspace/.tmp/e42_7-out.log","lines":8421}}
```

- `cmd` — argv, а не строка: ядро ничего не склеивает и не экранирует.
  Пайпы и редиректы — только если модель сама попросит `["bash","-lc","…"]`,
  и это исполняется внутри контейнера.
- Обрезка — забота песочницы: модель видит начало и конец, полный лог лежит в
  `/workspace/.tmp/`.
- `id` = `событие/шаг` — по нему потом можно вернуть асинхронный результат в ту
  же ветку.

## Безопасность

Что сделано специально:

- Песочница: `network_mode: none`, read-only rootfs, `cap_drop: ALL`,
  `no-new-privileges`, без секретов внутри. Наружу из неё не выйти.
- Белый список чатов: бот игнорирует всех, кроме перечисленных id. Без него
  любой, кто узнал адрес бота, получил бы доступ к серверу.
- Секреты живут только в `/etc/hermit/hermit.env` (600) и не попадают ни в
  `behavior/`, ни в контейнер.
- `behavior/` примонтирован в песочницу только для чтения.
- Инструменты перечислены в `core/src/policy.rs` явно; всё остальное — отказ.

Что надо знать:

- Песочница пишет в `/srv/hermit/workspace`. Пока ядро читает поведение только
  из `behavior/`, это безопасно. Как только появится автозагрузка скиллов из
  рабочей папки, проверка поведения обходится тривиально — так делать нельзя.
- Провал события не ретраится автоматически: повторный `bash` может повторить
  side effects. Событие паркуется со state `dead`, причина — в журнале.
- Ключ бота и ключ LLM лежат в файле на диске. Права 600 и отдельный пользователь
  ОС — это нижняя граница, а не полноценное хранилище секретов.
